# 安全说明与剩余风险

## 这不是安全沙箱

本插件只分发说明和元数据。`allow_implicit_invocation: false` 控制隐式匹配，不是文件、网络或进程权限系统；插件清单的 `capabilities` 是展示元数据，也不能拦截系统调用。静态测试不会执行或证明模型遵守文字约束。

不宣称“风险全部堵住”“完全安全”或“任意环境放心跑”。真正的边界依靠 Codex 宿主权限、操作系统、容器/虚拟机、网络策略与人的审批。请勿将生产凭据、真实业务数据或高权限开发环境用于未经验证的视觉循环。

## 针对的风险

本版本针对截图/素材/工具输出中的间接提示注入、Blender 动态代码执行、递归 Agent、项目构建副作用、浏览器远程加载、路径/链接越界、凭据传播、自动 Git 写入和额度消耗进行行为约束。所有输出仍需人工 review。

未知 3D 资产可能触发解析器漏洞；已装依赖可能被污染；进程可能继承环境或自动加载 `.env`；本机预览服务器可能暴露文件；链接、挂载和并发替换可能破坏路径检查。文本规则与模块黑名单无法完全消除这些风险。

## 宿主侧建议

先由用户配置低权限、无敏感文件的独立项目副本或一次性 VM/容器。不要挂载 SSH/cloud 凭据、kubeconfig、浏览器资料、Docker socket、宿主根目录或生产目录。渲染需要 GPU 时只提供必要设备，不以 `--privileged` 替代细粒度权限。

可在支持对应参数的 Codex CLI 中，由用户从目标项目启动：

```text
codex --sandbox workspace-write --ask-for-approval untrusted
```

这里保留工作区编辑，并对不可信命令要求审批。安装插件不会自动执行这条命令，也不会改写个人 `config.toml`、规则或审批设置。以本机 `codex --help` 和组织策略为准，不允许 Agent 自行启用全权限或自动审批。

**workspace-write 不能简单理解成“项目外文件绝对读不到”**，实际读取权限与平台和权限配置有关。需要保密的文件应不暴露给运行环境，而不是只依靠“不准读”的提示。外网与 loopback 是否允许也由宿主实施；必须考虑浏览器、渲染器和子进程，不只限制终端中的下载命令。

若使用外部图像/模型服务，明确允许的内容、服务和预算。截图进入原生评审/生成工具仍属于模型处理，不是纯本地文件操作；涉及私有项目时需先确认可传输范围。

## 审批原则

运行已审查项目命令不等于授权下载、安装、上传或提交；授权一个素材来源不允许其他来源。敏感凭据、越权提权、递归 Agent 和安全关闭不是视觉任务所需能力，不提供宽泛的“一键放行”。用户要求改变实际权限时，应作为独立的设置任务处理，而不是由本技能静默更改。

停止时检查本次进程和文件清单；没有权限关闭进程就报告，不冒充已清理。撤销插件只停用其工作流，不回滚已经产生的代码/素材；修改成果应通过用户审阅的差异处理。
