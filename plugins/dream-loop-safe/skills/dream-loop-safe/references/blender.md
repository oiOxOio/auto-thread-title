# Blender 执行检查

Blender Python 是完整可执行代码，不是沙箱。人工或模型预检只能降低风险，不能证明安全；未发现危险关键词也不能代表脚本安全。

## 运行前

只使用已安装的可信 Blender，不扫描家目录寻找可执行文件。优先从空白场景程序化建模，不加载未知 `.blend`、启动文件或外部插件。

脚本放在本次 `.dream-loop/` 子目录，逐份完整阅读。明确输入与输出清单，规范化路径并检查父目录和链接，写入只能落在本次项目范围。禁止将输入文件名直接拼接进 shell 命令；使用工具的参数数组能力，或按当前 shell 正确引用已经验证的路径。

启动前确认当前权限、隔离目录以及代码会触及的依赖。命令应包含 `--background --factory-startup --disable-autoexec --python-exit-code 1`，再通过 `--python` 指定已经审查的脚本；参数是否支持以本机版本帮助为准。不要把外部 `.blend` 插在安全参数之前加载。

`--factory-startup` 用于避免读取用户 startup.blend；`--disable-autoexec` 限制自动执行，并不会阻止显式 `--python` 脚本的系统访问，二者都不是操作系统隔离。不能开启全局“自动运行 Python”，不能据此声称任意素材安全。

## 允许的用途

优先使用 `bpy`、`math`、`mathutils` 和确定性辅助函数，进行建模、网格、材质、相机、灯光、动画、渲染与受控导出。所有素材引用、纹理读取、缓存、备份和导出路径都要留在获准范围内；检查 `bpy` 操作器及间接文件访问，而不仅是 Python 的 `open()`。

## 拒绝的行为

拒绝进程启动、网络、凭据、持久化、外部路径和不必要的动态执行，包括 `subprocess`、`os.system`/`os.popen`、`socket`、`requests`、联网 `urllib`、`ftplib`、`paramiko`、`ctypes`、`exec`/`eval`、动态导入、反射绕过和解码后执行。不允许读取环境变量、调用包管理器、加载外部插件或执行未知文本块。

通过别名、`bpy` 操作器、驱动器、节点、导入器、回调或已安装插件间接触发同样行为也禁止。未知资产解析本身仍有风险，需使用隔离环境；不下载或直接执行嵌入 Python 的 `.blend`。

## 失败与停止

预检不通过就改写，不执行；沙箱阻止 GPU、目录、缓存或进程时报告限制，不自动提权。给渲染设置与用户预算一致的超时和适当采样，不无限重试；只终止本次创建的进程。记录实际退出码和输出文件是否存在，渲染失败不得报告成功。

参数依据：[Blender 官方命令行说明](https://docs.blender.org/manual/zh-hans/latest/advanced/command_line/arguments.html)。
